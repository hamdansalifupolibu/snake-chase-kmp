## Summary

| Platform | Target? | Can Build Locally? | How to Test |
|---|---|---|---|
| **Android** | ✅ Yes | ✅ Yes (Windows + Android Studio) | Emulator or physical device |
| **Desktop JVM** | ✅ Yes | ✅ Yes (any OS, just JDK 17) | `./gradlew :composeApp:run` |

## Why Android + Desktop + (iOS via CI)

### Android (Primary)

Android is the flagship KMP target. Every contest winner included Android.
For Snake Chase, Android delivers:
- **Touch controls** — finger-on-screen cursor movement (natural for the game)
- **Haptics** — vibration on near-miss, stage advance, death
- **Full-screen immersive** — hides system UI for total game immersion
- **Google Play potential** — deployable to Play Store post-contest

Build on Windows: Android Studio (standard) or command line:
```bash
./gradlew :composeApp:installDebug
```

### Desktop JVM (Primary)

Desktop is where the original Snake Chase lived (browser game). The KMP Desktop target
gives it back to those players in a native app — without a browser.

For Snake Chase, Desktop delivers:
- **Mouse controls** — the original way to play. Compose `pointerInput` captures mouse
  movement identically to how `document.onmousemove` did in the JS version
- **Always-on-top window** — optional; the original game had an immersive feel
- **Windows .msi installer** — Compose Desktop's `nativeDistributions` generates it
- **macOS .dmg** — generated by the same Gradle task (for judges who have Mac)

Build on Windows:
```bash
./gradlew :composeApp:run           # run in development
./gradlew :composeApp:packageMsi    # build Windows installer
```

### iOS (Configured, CI-verified)

Without a Mac, we cannot run `./gradlew :composeApp:iosSimulatorArm64` locally.
However, the code is fully written and verified via GitHub Actions.

**Why include iOS at all?**
- iOS support is what separated 1st and 2nd place from 3rd place in 2026
- The shared module is **identical** regardless — judges can see this in the code
- The iOS `actual` implementations are written and committed
- GitHub Actions proves it compiles on a real macOS environment
- The README shows CI badge: ✅ iOS Build Passing

**What the CI does:**
```yaml
# Runs on: ubuntu-latest for Android/Desktop, macos-latest for iOS
jobs:
  ios:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: 17 }
      - name: Compile iOS shared module
        run: ./gradlew :shared:compileKotlinIosSimulatorArm64
      - name: Run shared tests on iOS simulator
        run: ./gradlew :shared:iosSimulatorArm64Test
```

## What "Shared" Means — The Technical Argument

The KMP score isn't just about Kotlin % — it's about how much is truly shared.

Here is the complete list of what lives in `commonMain` (shared across ALL platforms):

| Feature | In commonMain | Platform-specific |
|---|---|---|
| Game loop (60fps) | ✅ `withFrameMillis` | ❌ Nothing |
| Canvas rendering | ✅ `Canvas { }` composable | ❌ Nothing |
| Touch + mouse input | ✅ `pointerInput` modifier | ❌ Nothing |
| Keyboard input | ✅ `onKeyEvent` modifier | ❌ Nothing |
| Snake AI engine | ✅ Pure Kotlin | ❌ Nothing |
| Collision detection | ✅ Pure Kotlin | ❌ Nothing |
| Scoring engine | ✅ Pure Kotlin | ❌ Nothing |
| All 5 level configs | ✅ Kotlin data classes | ❌ Nothing |
| Obstacle system | ✅ Pure Kotlin | ❌ Nothing |
| Particle system | ✅ Pure Kotlin | ❌ Nothing |
| Game state (MVI) | ✅ StateFlow + ViewModel | ❌ Nothing |
| Leaderboard API | ✅ Ktor HTTP | ❌ Nothing |
| Multiplayer client | ✅ Ktor WebSocket | ❌ Nothing |
| Local scores (DB) | ✅ SQLDelight runtime | ❌ Nothing |
| Preferences | ✅ Multiplatform Settings | ❌ Nothing |
| All navigation | ✅ Compose Navigation | ❌ Nothing |
| All UI screens | ✅ Compose composables | ❌ Nothing |
| DI declarations | ✅ Koin shared module | ❌ Nothing |
| Serialization | ✅ kotlinx.serialization | ❌ Nothing |
| **Sound playback** | ❌ expect interface | ✅ actual per platform |
| **Haptic feedback** | ❌ expect interface | ✅ actual per platform |
| **SQLite driver** | ❌ provided by platform DI | ✅ driver per platform |

**Only 3 things need platform-specific code.** Everything else is shared.

```kotlin
// Uses javax.sound.sampled for cross-platform JVM audio
actual class AudioManagerImpl : AudioManager {
    actual fun playSfx(soundId: SoundId) {
        val stream = AudioSystem.getAudioInputStream(getSfxResource(soundId))
        val clip = AudioSystem.getClip()
        clip.open(stream)
        clip.start()
    }
}
```

```kotlin
// Calls AVAudioPlayer via Kotlin/Native ObjC interop
actual class AudioManagerImpl : AudioManager {
    actual fun playSfx(soundId: SoundId) {
        val url = NSBundle.mainBundle.URLForResource(soundId.fileName, withExtension = "mp3")!!
        val player = AVAudioPlayer(contentsOfURL = url, error = null)
        player.play()
    }
}
```
